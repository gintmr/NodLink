# NodLinkBridge（Mac 耳机桥）

在 Mac 上读取 AirPods 的头部姿态（`CMHeadphoneMotionManager`），按 [`docs/protocol.md`](../../docs/protocol.md) 通过 WebSocket 发给本机中继，同时执行调试台发来的指令：

- **全屏叠加层**：校准和测试时，在每块显示器上盖一层原生的半透明窗口，把目标红点画在真实屏幕上，不受浏览器窗口大小限制。
- **系统鼠标**：按调试台算出的位置（或位移）移动整台电脑的鼠标，跨显示器和真实鼠标一样。
- **显示器排列**：读取所有显示器的大小和相对位置报告给调试台。

校准和光标算法都在调试台里，这里只做输入输出，保证算法只有一份。调试台把数据源切到“耳机”即可使用。

不需要 Xcode，用命令行工具自带的 `swiftc` 编译，要求 macOS 14 或更新版本。

## 使用

1. 启动中继：`cd web && npm start`，然后打开 http://localhost:8787。
2. 把 AirPods 连接到**这台 Mac**（控制中心 → 声音，或者菜单栏的蓝牙图标），然后戴上。
3. 运行耳机桥：

   ```bash
   cd mac/NodLinkBridge
   ./run.sh                 # 第一次运行会自动编译
   ./run.sh --silent-audio  # 同时播放静音音频，测试没有声音时追踪会不会停
   ```

   第一次读取时，系统会弹窗请求“运动与健身”权限，点“允许”。如果之前拒绝过，到 系统设置 → 隐私与安全性 → 运动与健身 里打开 NodLinkBridge。

4. 调试台左下角的数据源选“耳机”。
5. 要让头部控制整台电脑的鼠标，在“光标”页打开“接管系统鼠标”。第一次会请求“辅助功能”权限（系统设置 → 隐私与安全性 → 辅助功能）；没有这个权限时光标也能移动，但其他 App 收不到悬停事件。任何时候按 Esc 交还鼠标。
6. 接管后用歪头点击：左歪回正单击（连做两次双击），右歪回正右键，左歪停住按下左键（之后转头就是拖拽，再歪一次松开）。点击需要“辅助功能”权限。
   动一下真实的鼠标、触控板或键盘，头控立刻让位，停手 1.5 秒后恢复，光标从你手动放下的位置接着走。点击时 AirPods 里会有提示音（系统音效）。
   改完代码后重新运行 `./build.sh`。`build.sh` 用 Bundle ID 作为签名身份，重新编译后系统权限（运动、辅助功能、麦克风、语音识别）应当保留；从旧版本升级上来时需要再授权一次。日志追加在 `bridge.log` 里。
7. 语音指令：在“光标”卡片 → “点击与防误触”里打开。第一次会请求“麦克风”和“语音识别”权限。只在接管鼠标期间听，默认用 Mac 自带麦克风。

> 每次重新编译后签名会变，macOS 可能会要求重新允许“运动与健身”和“辅助功能”权限。

终端每秒打印一行：设备端采样率、yaw/pitch/roll（度）、中继连接状态，以及这一秒发出的消息数。按 Ctrl+C 结束。

## 参数

| 参数 | 说明 |
|---|---|
| `--url <地址>` | 中继地址，默认 `ws://localhost:8787/ws?role=source` |
| `--silent-audio` | 循环播放静音音频 |
| `--voice-listen <秒>` | 只测语音：用 Mac 自带麦克风听这么多秒，日志里写出认到的指令，不连中继、不读耳机。加 `--langs en-US` 只用一种语言，加 `--default-mic` 用系统默认输入 |
| `--voice-test <音频文件…>` | 只测语音：把几个录音（同一种格式，如 `say` 生成后用 `afconvert -f WAVE -d LEF32@16000 -c 1` 转的）依次当作麦克风，按真实速度喂进识别流程，日志里每个文件开头写“自测片段 文件名” |
| `--old-post` | 说完后的补认用旧识别器（只认英文），不用 macOS 26 的新版识别器 |
| `--voice-record` | 录真人语音做基准：按终端提示把 16 条指令各念 3 遍，每句存成 WAV（`~/Library/Application Support/NodLink/recordings/`，只在本机），之后用 `--voice-test` 喂回去打分 |
| `--no-lm`、`--lm-weight <0～1>` | 关掉指令语言模型 / 调它的权重（部分系统上编译会失败，失败时自动不用） |

语音开着时，日志每 10 秒写一行“语音诊断”：收到多少块音频、最大音量、底噪、检测到几次开口、中英文各认出几次。说了没反应时先看这一行：音频是 0 块说明麦克风没声音（会自动重开），开口是 0 次说明音量检测没触发，开口有但识别结果没有说明是识别器的问题。

## 文件

| 文件 | 内容 |
|---|---|
| `Sources/main.swift` | 读取姿态、连接中继、发送 `motion`、`hello`、`event` 消息 |
| `Sources/VoiceGrammar.swift` | 语音指令的语法：识别出的文字 → 指令 |
| `Sources/CommandModel.swift` | 指令短语的自定义语言模型（系统识别器） |
| `Sources/Dictation.swift` | 说完后用 macOS 26 的新版识别器补认 |
| `Sources/AudioFile.swift` | 录下的指令存成 WAV（`--voice-record`） |
| `Info.plist` | 运动权限的说明文字；作为后台程序运行，不在程序坞显示 |
| `build.sh` | 编译并打包成 `build/NodLinkBridge.app`，做本地签名 |
| `run.sh` | 通过 `open` 启动 App，系统才会为它单独申请权限；日志输出到当前终端 |

## 语音识别

只用 macOS 自带的识别器，不需要下载任何模型，也都在本机离线识别：

- 说话时：`SFSpeechRecognizer` 实时识别（中文 + 英文），配合指令短语的自定义语言模型（`Sources/CommandModel.swift`）。
- 说完后没认出指令：macOS 26 以上再用新版识别器 `DictationTranscriber` 补认一遍（`Sources/Dictation.swift`）；更老的系统用旧识别器按英文补认。
- 识别出的文字统一交给 `Sources/VoiceGrammar.swift` 解析成指令。
